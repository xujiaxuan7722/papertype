# PaperType（纸卷上机）最终方案

项目名：papertype（仓库、Python 包同名；程序 PaperType.exe；中文名「纸卷上机」）
日期：2026-09-11　状态：最终方案（09-11 第二版：去掉答案隐藏字段，OCR 改为导入页可选入口），按此开工　路线：Python 后端 + 浏览器界面　底稿：机考刷题系统方案-2026-09-10.md（项目定名前的名称）（含你的批注，已全部吸收）

把一份 Word、PDF 或图片试卷变成能在电脑上作答的电子卷，练机考手感。系统只汇总作答，不判分、不倒计时，一人在 Windows 笔记本上单机使用。

---

## 1. 目标与边界

**做什么：** 导入试卷，自动识别成题目，人工校正后生成电子卷；勾选选择题、输入填空题；提交时提示未作答题号，输出一张"题号 / 题型 / 我的答案"表。导入页由你二选一：「导入文件」走 Word / PDF 文字层直提，「OCR 识图」走本地 OCR；识别结果可按你的选择交给大模型整理。

**不做什么：** 不判分，不倒计时，不处理数学公式，不做多人账号，不上服务器。混排卷里的答案和解析在导入时直接丢弃，系统里不保存。

## 3. 技术路线（已确认）

**Python 后端（FastAPI）+ 浏览器界面，PyInstaller 打包成单个 PaperType.exe。**

选它而不是纯网页的理由：

- 解析层是核心难点。Word 自动编号的题号、下划线格式的空位，python-docx 和 PyMuPDF 能直接读到属性。
- 两份真题的分析证明必须用 PyMuPDF：过滤旋转水印、按题裁剪截图，浏览器里做不到。
- OCR 引擎（RapidOCR，onnxruntime 推理）只能在 Python 侧跑，纯网页做不了 R15。
- 数据存磁盘，试卷和作答记录是 data 目录下的 JSON 文件，随便拷走。
- 能用真卷子做 pytest 回归测试，改规则不怕改坏。

| | 纯网页 | Python 后端（选定） |
|---|---|---|
| 运行方式 | 双击 index.html | 双击 PaperType.exe，自动打开系统默认浏览器（见 §8.8） |
| Word / PDF 解析 | JS 库，编号与空位需自拆 XML | python-docx、PyMuPDF |
| 水印过滤、按题截图、OCR | 做不到 | 可做 |
| 数据存放 | 浏览器本地存储 | 磁盘 JSON 文件 |
| 调大模型 | 浏览器直连，可能被跨域拦 | 后端调 |
| 代价 | 零安装 | exe 约 150 到 200 MB（含 OCR 模型），首次启动 2 到 5 秒 |

## 4. 两份真题的分析结果

用中国银行押题卷（33 页，Word 2013 导出）和工商银行 2021 真题解析（34 页）做了实测。

### 4.1 共同点

- 两份都有文字层，走直提路径，不需要 OCR。
- 两份都有满页水印和页眉页脚广告。中行卷是旋转 30 度的"海哥讲银行"，每页 9 处，共 927 个碎片混在正文里；工行卷是横排的"银行笔试助攻加微信"加淘宝店地址加页码，每页都有。
- 两份都有图形推理题，题干和 A B C D 四个选项全是图片，文字层里只剩"A."四个空标签。
- 两份都有资料分析题，表格和图表抽成文字后变成一串数字，不可读。
- 两份都有材料题：完形填空、阅读理解、资料分析都是一段材料下挂多道小题。
- 题目跨页很常见。

### 4.2 各自特点

| | 中国银行押题卷 | 工商银行真题解析 |
|---|---|---|
| 答案 | 无，是纯试卷 | 每题后紧跟"【答案】C。第一步……" |
| 题号 | 三个单元各自从 1 重新编号（英语 1-55、行测 1-58、综合 1-55，共 168 题） | 1 到 80 连续 |
| 选项排版 | 常见 A B 同行、C D 同行 | 每个选项独占一行 |
| 分区标题 | 有"第一单元 英语""一、选词填空" | 无，只有开头一张题量表 |
| 文件健康 | 正常 | xref 表损坏，PyMuPDF 可自动修复读取 |

### 4.3 实测验证过的两个办法

- **水印过滤：** 中行卷的水印文字行方向是 (0.87, -0.48)，正文全是 (1, 0)，按方向一刀切干净。工行卷的水印是横排的，但同一字符串在 34 页里每页出现，正文不会这样，按"出现页数超过一半"过滤。两个规则叠加用，短于 4 个字的纯标点串不参与频率统计，否则"）。"这类会被误杀。
- **按题裁剪截图：** 以每个题号所在行的纵坐标为锚，从本题题号到下一个题号之间的区域渲染成一张图。对中行卷第 15 页实测，数列题裁出来题干、数列、四个选项完整清晰。图形推理、资料分析的图表靠这张图作答，你仍按字母勾选。

### 4.4 OCR 实测（R15）

把两份卷子各取一页渲染成图片，用 RapidOCR 在本机 CPU 上识别，和文字层逐行比对：

| 页面 | 分辨率 | 正文行数 | 逐行相似度 ≥ 0.9 的比例 | 耗时 |
|---|---|---|---|---|
| 中行卷第 15 页（数列、图形推理） | 150 dpi | 38 | 89% | 2.5 秒 |
| 工行卷第 10 页（数字运算带解析） | 150 dpi | 33 | 85% | 2.7 秒 |

没对上的行主要是三类：全角逗号被识成半角（"4，11"变"4,11"，对作答没影响）；被水印切断的碎行；长题干换行处合并错。题号、选项字母、选项内容基本都对。结论：清晰的截图和扫描件，OCR 后走同一套规则切题可用；手机拍照的歪斜、阴影页面会更差，这类卷子建议开大模型整理档（§8.5）。

引擎选 RapidOCR 的原因：PP-OCRv6 模型转成 onnx，纯 CPU 离线跑，中英混排识别好，打进 exe 约增加 100 MB；Tesseract 中文差，PaddleOCR 原版依赖整个 Paddle 框架打包太重。

### 4.5 你给的两张图片实测（R15）

| 图片 | 内容 | 识别行数 | 字词错误 | 耗时 |
|---|---|---|---|---|
| 行测截图（1280×1611） | 类比、图形推理、逻辑填空、片段阅读各一题 | 36 | 0 | 2.9 秒 |
| 建行模拟卷（1170×1578） | 单选 6 题 | 36 | 0 | 2.2 秒 |

两张图所有汉字、字母、数字、百分号全部识别正确，一个错字都没有，建行卷 36 行里 30 行置信度 0.98 以上。剩下的问题全是版面层面的，不是识别层面的，靠坐标处理：

- **题号独立成列：** 行测截图的"2.""3.""4."和题干之间隔了一段空白，OCR 把题号和题干拆成两个框，第 2 题的题号甚至单独成行。处理：同一纵坐标上的框按横坐标合并成一行，题号框在最左即归入该行。
- **填空空位：** 第 3 题的两条横线 OCR 不认，但同一行被切成"…不同的社会"和"中，这里…"两个框，中间有一段明显的横向空隙。处理：同行相邻框之间的间距超过两个字宽，就在此处补一个 `____`。
- **同行双选项：** "B.模式　偏差"被拆成"B.模式"和"偏差"两框，"A.形态歧义"则连在一起。处理：同行按横坐标归并后，再按 A 到 D 字母切分，字母之间的文字全归前一个选项。
- **图形推理：** 第 2 题只识别出"?"和 A B C D 四个字母，题干和选项全是图。处理：题号到下一题号之间文字极少而图像面积大，判为图片题，从原图按纵坐标裁一张挂上，你看图选字母。
- **括号：** "（　）"被识成"()"，不影响作答。

结论：清晰截图和扫描件的 OCR 准确率接近文字层直提，可以放心用；真正要做的是坐标归并这一层，已经写进 §8.1。手机斜拍、有阴影的照片仍会掉准确率，那种情况才需要开大模型整理。两张图已存到 ~/下载/papertype样卷/ 作为回归用例。

## 5. 题目和答案混排怎么办（R13）

导入只产出题目。解析器把"答案"和"解析"当作独立部分识别并丢弃，不写入试卷文件，系统里不存在答案数据。

- **识别标记：** 【答案】X、答案：X、正确答案：X、参考答案：X、故本题选 X、题干括号里已填的字母（ C ）。标记之后到下一题号之前的文字视为解析，一并丢弃；题干括号里的字母清空还原成"（　）"。
- **不保留：** 试卷 JSON 里没有 answer、analysis 字段，校正页、作答页、汇总页都不出现答案。你对答案时自己拿原卷看。
- **纯试卷后补答案：** 不做。
- **风险：** 解析里出现的"A 选项……排除 A"不会误伤题干，因为只从答案标记处开始截断。答案标记缺失、解析混进题干时，该题按"题干过长"标"待核对"。

## 7. 数据流

1. 导入：导入页三选一。「导入文件」拖入 docx / pdf；「OCR 识图」拖入 jpg / png（可多张）或扫描版 pdf；「粘贴文本」
2. 分流：按你选的入口走。「导入文件」里遇到无文字层的 pdf，提示改用「OCR 识图」，不自动切换
3. 清洗：去水印、页眉页脚、页码（§4.3 的两个规则）
4. 抽取：统一成"带结构的文本行"，每行附编号信息、空位数、页码、纵坐标、来源（直提 / OCR）
5. 规则切题：本地毫秒级，零费用，不联网
6. 丢弃答案：识别答案标记，从标记处截断，不保存
7. 分组与截图：材料题成组；每题按锚点裁剪一张图（OCR 路径从原图裁）
8. 校验：题号连续、选项不少于 2、填空至少 1 空；不过的题标"待核对"
9. 校正：逐题改题型、选项、空数，可合并拆分；可按你的选择送大模型整理
10. 保存试卷：data/papers/<id>.json
11. 作答：整卷预览或分题作答，共用作答记录
12. 提交：先列未作答题号
13. 汇总：题号 / 题型 / 我的答案，可复制、导出 Excel

## 8. 模块设计

### 8.1 导入器

- **docx：** python-docx 读段落；题号取自编号属性自行计数；run 下划线属性还原成 `____`；内嵌图片挂到所属题；表格按行展开。
- **pdf（有文字层）：** PyMuPDF。先按 §4.3 过滤水印和页眉页脚；按行纵坐标排序，同行多选项拆分；每题按锚点裁图存 data/assets。
- **OCR 识图（R15，你在导入页主动选）：** 输入 jpg / png（单张或多张，按文件名顺序拼成一份卷）和扫描版 pdf（先逐页渲染成 150 dpi 图片）。RapidOCR 识别，自带方向分类纠正 90 度旋转；输出每个文字框加坐标。坐标归并层（§4.5 实测得出的四条规则）：同纵坐标框合并成行、题号框归入所在行、同行大间距补 `____`、同行按 A 到 G 字母切选项。之后转换成和 pdf 路径同样的"带结构的文本行"。图片题的裁图直接从原图按纵坐标裁。OCR 来源的行带 source=ocr 标记，校验更严（§8.3）。导入完成后显示"本卷经 OCR 识别，M 题待核对"，手机照片类效果差时你再手动点大模型整理。
- **文本：** 粘贴框直接进解析器，豆包转出的内容走这条路。

### 8.2 解析器

- 题号写法：1.　1、　1．　第1题　1:　编号属性序号。题号前允许残留的水印碎片；OCR 路径额外允许"1,""l."这类常见误识。
- 单元题号重置：遇到"第 N 单元"时开新单元，题目唯一标识是"单元 + 题号"，答题卡按单元分区显示。
- 选项写法：A.　A、　A　同行多个选项按坐标拆分；支持到 G。
- 题型判定优先级：分区标题 > 选项结构 > 题干特征 > 空位数。分区下的题继承分区题型。无分区标题时默认单选。
- 多候选评分：几种切分假设分别解析，按题数合理性、选项完整度、题号连续性取最优。
- 材料题：分区标题为完形填空、阅读理解、资料分析，或两个题号之间夹着超过 5 行非选项文字时，把材料和后续小题成组；作答时材料固定在上方。
- 图片题：题干或选项文字为空但该区域有图片对象时，标为图片题，作答页以裁剪图为主体。

### 8.3 校验

题号连续；选择题选项不少于 2；填空至少 1 空；题型有来源；有答案标记的卷子每题都应有答案。OCR 来源的题额外检查：选项字母 A 到 D 齐全、题干长度不短于 6 字、无连续三个以上非中英文字符。任一不过标"待核对"，校正页标红置顶。

### 8.4 存储

- `data/papers/<id>.json` 试卷：题目列表、来源文件、导入路径（直提 / OCR）、导入时间、每题 reviewed 标记。不含任何答案字段。
- `data/attempts/<试卷id>/<时间戳>.json` 作答记录，每次提交一份，作答中每 10 秒自动存草稿。
- `data/assets/<试卷id>/q_<单元>_<题号>.png` 按题裁剪图；`pages/` 存原始图片或渲染页。
- 导出 Excel 列：单元、题号、题型、题干、A、B、C、D、我的答案。

### 8.5 大模型（R8、R9、R14、R16）

**总开关：** 设置页里的开关和密钥。未填密钥或关闭时，下面所有大模型按钮置灰，程序里不存在自动外发的路径。

**接口：** 商汤网关 token.sensenova.cn/v1，OpenAI 兼容格式，模型 deepseek-v4-flash（网关里现有的 DeepSeek 型号，设置页可改）。直连不走代理。

**四种用法，全部由你在界面上手动触发：**

| 用法 | 在哪触发 | 做什么 |
|---|---|---|
| 仅规则（默认） | 导入页默认档 | 本地秒出，零费用，不联网。标红题手动改 |
| 标红题重切 | 导入页第二档 | 只把待核对的题送去重切，其余不动。送之前弹确认，写明题数 |
| 整卷重切 | 校正页按钮 | 你觉得切得太乱时手动点 |
| OCR 整理（R16） | 校正页按钮，OCR 卷默认推荐 | 把 OCR 文本交给模型修错字、合并断行、补全选项字母，输出标准格式文本 |

**约束：** 按大题分块每块不超过 20 题；逐字抄写不许改写，OCR 整理只允许修正明显错字；温度 0；输出标准格式文本回流解析器和校验；并行发请求带进度条；模型产出的题一律标"待核对"，校正页里你逐题过一遍。

**二期候选：** 商汤网关里的 sensenova-6.8-flash-lite 能看图，可以做"看图重切"，直接对着试卷图片出题目。效果未验证，首版不接，等 OCR 路径跑顺后再试。

### 8.6 前端五页（R11）

- **导入页：** 三个入口并排：「导入文件」（Word / PDF）、「OCR 识图」（图片 / 扫描件）、「粘贴文本」，由你选；选识别档位；导入后显示"共 N 题，M 题待核对，K 题带图"。
- **校正页：** 左侧原文或原图（含裁剪图），右侧题目列表；每题可改题型、题干、选项、空数，可合并、拆分、删除、改单元；待核对题标红置顶；"整卷重切""OCR 整理"按钮在此；确认后保存。
- **整卷预览：** 一页按原顺序显示全卷，按单元分段，可滚动通览，可直接作答。
- **分题作答：** 一屏一题；右侧答题卡按单元分区显示题号，已答、未答、标记三色；点题号跳转；上一题 / 下一题；数字键 1 到 7 选选项，回车下一题；单选为单选框，多选为复选框，填空按空数给输入框；图片题显示裁剪图。
- **汇总页：** 提交前弹未作答题号清单，可返回补做或直接提交；提交后显示汇总表；一键复制、导出 Excel。

### 8.7 作答与汇总规则

- 两种模式共用同一份作答记录，切换不丢答案。
- 提交时若有未作答题，弹出"还有 X 题未作答：3、7、12"，可返回补做或直接提交。
- 汇总表列：单元、题号、题型、我的答案；未作答显示"未作答"；多选按字母顺序拼接；多空填空用分号分隔。
- 不判分，不计正确率，不倒计时。

### 8.8 入口、浏览器与打包（R10）

- **启动：** 双击 PaperType.exe，程序在 127.0.0.1 上随机选一个空闲端口起服务，然后调用 Windows 的默认浏览器打开这个地址。**跟随系统默认设置**，你平时用什么浏览器就弹什么，Windows 10 / 11 默认是 Edge。
- **要求：** Edge、Chrome、Firefox 近两年的版本都可以。
- **兜底：** 浏览器没有自动弹出时，exe 的黑窗口里会打印完整地址，复制到任意浏览器地址栏即可。
- **可选：** 设置里可勾选"应用窗口模式"，用 Edge 或 Chrome 的 --app 参数打开，没有地址栏和标签页，更像考试软件。默认不勾。
- **打包：** PyInstaller 打单个 PaperType.exe，OCR 模型文件随包内置；连同 data 目录放在 PaperType 文件夹里，拷到 Windows 笔记本双击即用，不需要装 Python。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Word 自动编号题号不在正文 | 整卷切不开 | 读编号属性计数；仍失败提示在 Word 里"把编号转为文本" |
| 填空空位是下划线格式，PDF 文字层拿不到 | 空数丢失 | docx 读 run 属性；PDF 靠"（ ）"和连续下划线字符；校正页一键设空数 |
| 水印碎片混入题干和题号前 | 题号识别失败、题干多字 | 方向过滤加频率过滤；题号正则允许前缀残留 |
| 图形推理、资料分析全是图 | 文字层空 | 按题裁剪图为主体作答 |
| 单元题号重置 | 题号冲突 | 唯一标识为单元 + 题号 |
| 答案解析混排 | 作答时泄露答案 | 标记识别后截断丢弃，不落盘 |
| 无分区标题时单选多选难分 | 题型错 | 默认单选，题干含"多选""哪些"判多选；校正页批量改 |
| PDF 双栏、跨页题 | 顺序乱、题被截断 | 按坐标排序，跨页合并同题号，裁剪图可跨页拼接 |
| OCR 版面：题号独立列、空位不认、同行双选项 | 切题错位、空数丢失 | §4.5 四条坐标归并规则；OCR 卷校验更严；所有 OCR 题在校正页过一遍 |
| 手机拍照歪斜、阴影 | OCR 准确率明显下降 | 导入前提示尽量用截图或扫描；方向分类纠正；效果差时用豆包转 Word 兜底 |
| 大模型漏题或改写题干 | 题目失真 | 分块 20 题、逐字、温度 0、题号校验、产出一律待核对 |
| exe 体积和启动 | 首次启动慢 | OCR 模型懒加载，只在导入图片时初始化 |

## 11. 实施计划与验收

估算 5 到 7 个工作日，比上一版多 1 天，用于 OCR 导入器和 OCR 整理档。

1. **清洗与直提导入器**：PDF 水印过滤、页眉页脚过滤、按题裁图；docx 编号与空位。验收：两份样卷清洗后无水印碎片，每题一张裁剪图。
2. **解析器与回归测试**：切题、单元、材料题分组、答案丢弃、校验；pytest 固定两份样卷。验收：中行卷切出 55 + 58 + 55 共 168 题，工行卷 80 题且题干、选项里不残留任何答案和解析文字；待核对题不超过一成。
3. **OCR 识图入口**：RapidOCR 接入、坐标归并四规则、原图裁题。验收：你给的两张样图分别切出 4 题（含 1 道图片题、1 道两空填空）和 6 题，选项齐全；中行卷第 15 页渲染图经 OCR 切出的题数与直提路径一致；单页耗时 3 秒内。
4. **前端作答**：五页。验收：一份样卷从导入到汇总走通；切换模式答案不丢；提交前正确列出未答题号；导入页三个入口都能进。
5. **大模型四种用法**：总开关、商汤接口、标红题重切、整卷重切、OCR 整理。验收：开关关闭时抓包无任何外发请求；OCR 整理后回流校验，待核对题数下降。
6. **打包上 Windows**：PyInstaller 打 PaperType.exe，含 OCR 模型。验收：双击即开，默认浏览器弹出，data 目录随文件夹迁移；导入一张截图卷能识别。

## 12. 已定事项

1. 混排卷只导入题目；答案和解析在导入时丢弃，不保留任何隐藏字段，系统里没有答案。
2. 图形推理、资料分析这类图片题，以按题裁剪图作答，按字母勾选。
3. "贴入答案串"补答案的功能不做。
4. OCR 识图是导入页的一个独立入口，由你选择用它还是导入文件；引擎 RapidOCR，本地离线，内置 exe。两张样图实测零错字。
5. 商汤多模态看图重切放二期。
6. 浏览器跟随系统默认，可选应用窗口模式。

**开工后需要你补的一样东西（不阻塞）：** 一张手机斜拍的试卷照片，用来验证 OCR 在差图上的表现。
